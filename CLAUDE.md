# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

All tooling runs through `uv` — never raw `pip`.

```bash
uv sync --all-extras          # install deps (incl. dev)
uv run living-ink --help      # CLI: sync | watch | setup | status
uv run living-ink sync --notebook "Foo" --keep-temp   # single notebook, preserve artifacts
uv run living-ink sync --preview                      # say what a sync would do; no download, no OCR
uv run living-ink sync --preview --transcribe         # the expensive rehearsal: real OCR, publish nothing
uv run living-ink sync --json                         # run summary as JSON
uv run living-ink status                              # health check + effective settings
uv run living-ink watch --interval 600                # sync every 10 minutes until stopped
uv run living-ink status --json                       # machine-readable health check

uv run ruff check .           # lint
uv run ruff format --check .  # format check (run `ruff format .` to fix)
uv run pytest -v              # full suite
uv run pytest tests/test_pipeline.py::test_name -v    # single test
./tests/test_docker.sh        # Docker build + smoke tests (slow)
```

Before committing: `uv run ruff check . && uv run ruff format --check . && uv run pytest -v`.

## Architecture

Pipeline: reMarkable tablet → download → render `.rm` → PNG → OCR/cleanup via LLM → publish to destinations.

Six seams matter more than the file list:

**1. Transport is a Protocol, and it is self-healing.** `transport.RemarkableTransport` is the whole contract (`check_connection`, `get_meta_items`, `get_doc`, `download`, `get_file_type`, `download_raw_file`, `get_tags`). `api.get_rmapi()` returns a Cloud client (`sync.py`, sync protocol v3/v4), an SSH client (`ssh.py`, USB at `10.11.99.1`), or a `FallbackClient` wrapping both. Every method goes through `FallbackClient._with_fallback`, so a new Protocol method needs one proxy line, not bespoke retry logic. A transport that genuinely cannot serve a call raises `transport.UnsupportedOperation` — never omit the method, because callers do not use `hasattr`. `tests/test_transport.py` fails if any shipped client drops a method. `get_rmapi()` takes the resolved `Settings` and no longer reads the environment itself; preference resolves from `--ssh`/`--cloud` flags → `REMARKABLE_PREFERRED_CONNECTION` env → `preferred_connection` config → `"ssh"`.

**2. Destinations are an ABC with per-destination state.** `destinations/` is a package: `base.py` (the ABC, the registry, `DestinationStatus`, `MergeUnit`, `DestinationError`), `filesystem.py` (the publish lifecycle every file-writing destination shares), `markup.py` (the body-rendering contract), one module per destination, and `__init__.py` re-exporting the lot plus `build_destinations()`. **Registry order is publish order, and registry order is the import order in `__init__.py`, which is alphabetical** — "whose failure is reported first" is configuration, not an accident of an import statement. `ObsidianDestination` (Markdown + YAML frontmatter + WikiLinks, mirrors the full reMarkable folder tree) is the one 1.0 ships, and it is `enabled_by_default` because the only destination cannot be the one you opt into. Sync state is tracked **per destination** in `state.db` (`state.StateStore`, one `publications` row per `(doc_id, destination)` carrying the version, the `external_id`, and the `target` it landed on), so a notebook can be published to one destination and still pending for another. **A destination that stops shipping takes its rows with it:** `pipeline.get_state_store()` calls `StateStore.forget_unknown_destinations(registered_state_keys())` on the first open, after the legacy-JSON import. Registered, not enabled — a destination the user turned off keeps its rows, so a toggle is not a full re-sync — and an empty registry raises rather than deleting everything, because no destination at all is a failed import.

**A destination is handed two objects, and `publish(doc, ctx)` is the whole signature.** `core.document.Document` is what was read — `doc_id`, `title`, `folder_path` (a tuple of folder names, outermost first), `source`, `modified`, `tags`, `pages`, `body_text`, `source_file` — and `core.document.PublishContext` is what is known about publishing it *there* — `doc_id`, `dry_run`, `existing_external_id`, `existing_target`, `adopt_by_name`, `first_published`, `settings`. `publish` used to take twelve positional arguments, so adding one fact meant editing every destination, every call site and every test. Three things follow from the split. **The title is never glued to the folder**: `display_title = f"{folder} / {title}"` was split apart again inside the destination, so a notebook genuinely called `"Q1 / Q2"` was filed in a folder named `Q1`. **The text never round-trips through a file**: `_write_transcripts` writes an artifact for the user, nothing reads it back, and the pages reach the destination as pages. **A `Page` carries its own presentation facts** — `index`, `number` (what the *document* calls it, so an annotated 400-page PDF yields 12 and 377, not 1 and 2), `label`, `breadcrumbs`, `image_path`, `text`, `source_key` and `error` — all set at render time by `_describe_pages`. `Page.error` is the only way to tell a page that failed from a page that was blank; a rate-limited page renders a `> [!warning] Page not transcribed` callout (`obsidian._gap_marker`) instead of silently publishing nothing, and `error` and `text` are **not exclusive** — a page that salvaged part of its transcription and then failed publishes both, marker first, because discarding text the user has already paid for is the one thing worse than a gap. `Page.text` is body content only — the heading is the destination's to render (`extract.format_page_section_header`), because presentation does not belong in the payload.

**Every publish returns a `core.document.PublishResult`** (`ok`, `target`, `external_id`, `detail`, `warnings`) — a destination never records where a note landed on *itself*. It used to set `last_external_id` and `last_target` as instance attributes for the caller to read back, which made every destination stateful across documents and left the two facts free to describe different notes. `_publish` writes `result.external_id` and `result.target` into the publications row and feeds them back next time as `ctx.existing_external_id` / `ctx.existing_target`, so a renamed or moved notebook **moves** its note (with its attachments) instead of growing a second one. `result.warnings` go to `report.warn()` via `_report_destination_warnings()` — on failure too, since that is the run whose warnings matter most.

**The state key is declared, never derived.** `Destination.state_key` is what a publication row is filed under; it was `type(dest).__name__`, so renaming a class silently made every document look new — every note rewritten, every `first_published` restarted. Both shipped keys are pinned to their historical class names; `register_destination` raises `TypeError` unless the class sets `state_key` in its own `__dict__` (an inherited one would make two destinations share rows). `display_name` is the cosmetic counterpart, free to change, defaulting to `config_key`. Read state with `state_key`, print with `display_name`, and never swap them.

**Construction never validates; `check()` reports and preflight refuses.** `ObsidianDestination.__init__` used to raise for a missing vault, `build_destinations` caught it into one warning, and the run then compared every document against zero destinations and exited 0 having published nothing. Now `check()` returns a `DestinationStatus(ok, detail, remedy)` — cheap, no round trip — and `SyncPipeline.preflight_destinations()` runs right after `connect()`, checking *every* enabled destination (not just the first to fail) and raising `ConfigurationMissing` if any fails or if none are enabled. `cli.collect_status` calls the same `check()` rather than keeping a second copy of the vault test.

**`merge_unit` says how much of an existing note a re-publish rewrites** (`MergeUnit.DOCUMENT` / `.PAGE`, `str`-mixin enum because the floor is Python 3.10). The ABC defaults to `DOCUMENT`; Obsidian, the one destination 1.0 ships, declares `PAGE`. `--preview` reads it to promise the right thing before the run instead of after. Never branch on a class name to decide that.

**A destination that writes files gets its lifecycle from `filesystem.FileSystemDestination`, and the stage order is a dependency order.** `publish()` is fixed: `resolve_location` → `resolve_name` → **the dry-run cut** → `prepare` → `write_attachments` → `render_body` → `render_metadata` → `commit`, passing one mutable `NoteLayout` (the scratch state; a destination holds none of it, so two documents in a run share nothing). **Stages 1 and 2 must be safe against a read-only vault** — that is what the cut is for, and it is why *both* `mkdir` calls live in `prepare`. Move one up into `resolve_location` and a `--preview --transcribe` starts scattering empty folders through the vault again. A stage that cannot continue raises `DestinationError`; `publish()` turns that and any `OSError` into a failed `PublishResult`, and `layout.warnings` reach the result on failure too. Every path is built through `self.contained(root, *segments)`, which resolves and asserts **before** `mkdir` — `_sanitize_filename` is cosmetic and leaves `..` and `.` untouched on purpose, so containment, not sanitizing, is the guarantee. `AttachmentPolicy` (`OWNED` / `BESIDE`) is the one question behind four behaviours that used to be four separate readings of `attachments_folder == ""`: whether the attachment directory can be moved wholesale, deleted wholesale, and whether page filenames need the note's name to stay unique. Ask the policy, never the blank string. `report_failure(summary)` / `clear_failure()` are no-ops on the ABC and write `<notes_root>/Living Ink — sync failed.md` here, carrying the reserved `living_ink_id: living-ink-sentinel` and no `publications` row; `clear_failure` only unlinks a file that carries that id, and `_claim_name` refuses to hand the name to a real notebook. `SyncPipeline._run_recorded()` calls one or the other in a `finally` — an interrupt is not a failure and a dry run reports nothing. `notemerge.inspect_existing()` returns three states, not two: absent, readable, and **unreadable** (invalid UTF-8, a lock, a directory in the way). Only `inspect_existing` may decide whether a path is free; `read_existing` flattens unreadable to `None` and is for callers that just want the text.

**Body text goes through `destinations/markup.py`, which cannot lose a block silently.** `to_blocks()` parses the canonical body (Obsidian-flavoured Markdown, deliberately — Obsidian is native on 19 of the 20 fidelity-matrix elements) into `Block(kind, text, level, attrs)`; a `MarkupWriter` subclass declares `handles` as an **explicit** frozenset of the `BlockKind`s it renders natively, and `render()` sends anything else to `degrade()`, which must return a `Degradation` the run report shows. Never write `handles = frozenset(BlockKind)` — a twelfth kind would then be silently claimed rather than degraded, which is the one failure the contract exists to prevent. A `BlockKind` exists only when the canonical body can plausibly contain it *and* at least one destination cannot represent it natively; `ocr_prompt.txt` and the enum move together. Adjacent blocks of one run are joined in `render()` via `tight_key`/`join_tight` rather than in `assemble()`, which only sees rendered strings and cannot tell a sibling list item from a new list. An ordered item keeps the number it was transcribed with — a handwritten page can legitimately start at 3. `tests/fakes.PlainTextWriter` exists because Obsidian degrades nothing, so nothing shipped exercises `degrade()`.

The **document id is the identity**, not the title: it arrives on both `Document` and `PublishContext`, Obsidian stamps it into the frontmatter as `living_ink_id` and steps around a same-titled note belonging to another document (`Notes (2).md`), and a destination that hands back an id replaces by that id. A document that has publications but is absent from the tablet's full listing is an orphan: `_handle_orphans()` reports it and deletes nothing unless `sync --prune`, which calls `Destination.unpublish()` — refused by default, and refused by Obsidian for any note not carrying the matching `living_ink_id`. Adding a destination means: a module in `destinations/`, subclass `Destination`, declare `state_key`, implement `from_config(section, settings)` + `describe()` + `check()` + `publish()`, decorate with `@register_destination("<config section>")`, and add the import to `__init__.py` in alphabetical position. `destinations.build_destinations()` walks `DESTINATION_REGISTRY`, so nothing in `pipeline.py` needs editing. A `from_config` returning `None` (or raising) skips that destination with a warning instead of failing the run. A destination reads its **values from `settings`, not from the `section`** — the section decides whether the destination runs, the settings decide how — so a flag or an env var outranks the file without the pipeline reaching in to patch the built object. The legacy single `destination:` key is normalized into per-section config by `_apply_legacy_destination()`, and the settings it could carry name `destination.<key>` in their `legacy_keys` so they still resolve. Obsidian's frontmatter dates are three distinct facts, not one: `created` (kept from the existing note if present, else `first_published` from the state store, else the tablet's modification date, else today), `updated` (the tablet's own modification date — `Document.modified`, read off the item by `DocumentJob.modified_at()`) and `synced` (today). `pipeline.to_datetime()` / `to_iso_date()` are the single place that reconciles the transports' disagreement about timestamp shape (datetime vs. ISO string vs. epoch seconds vs. the device's epoch milliseconds); parse timestamps there, not at the call site.

**3. AI is one universal OpenAI-compatible provider.** `providers.UniversalChatProvider` talks to Gemini, OpenAI, Ollama, Groq, OpenRouter, Mistral, Together, or a custom base URL — selected by `PROVIDER_PRESETS` (`providers.py:39`). `NoneProvider` disables cleanup (raw OCR passthrough). Any backend that speaks the OpenAI chat API is a **preset entry, not code**; one that does not is a `TextRepairProvider` subclass with a `from_config()` classmethod, decorated `@register_provider("<name>")`. `get_provider(settings)` takes the run's resolved `Settings` — never a config dict, because the API key is not in the config file — and checks `PROVIDER_REGISTRY` first, then the presets; a registered plugin's `from_config(settings)` gets the same object. `clean.configure(settings)` is the one call that builds the provider and records whether the AI pass runs at all (`clean.repair_enabled()`, `ENABLE_REPAIR`); it is called once per run from `load_yaml_config()`. Vision OCR and text repair are the *same* call path with different system prompts, loaded from `ocr_prompt.txt` and `cleanup_prompt.txt` (the only two prompt files; plain text shipped inside the package — edit these to change LLM behavior, not the Python). `clean.ocr_and_repair()` does OCR + cleanup in one multimodal request, and it is the *only* way a page is read: there is no second OCR backend, so a provider without vision support fails the preflight rather than degrading.

**4. CLI is Command Pattern; pipeline is a class.** `cli.py` registers `BaseCommand` subclasses (`LivingInkCLI.DEFAULT_COMMANDS`: `SyncCommand`, `WatchCommand`, `SetupCommand`, `StatusCommand`, `StateCommand`, `CacheCommand`) on `LivingInkCLI`, each owning its own `register_args()` + `run()`. `SyncCommand.execute_sync()` returns a bool so a caller can decide what a failure means; only `run()` exits. `WatchCommand` reuses both — it delegates `register_args` to `SyncCommand` and loops over `execute_sync`, surviving failed cycles and stopping on `ConfigurationMissing` or Ctrl+C, which is what the compose daemon service now runs. `SyncCommand` constructs a `SyncPipeline` from `cli.sync_arguments(args)` — the single place that knows CLI flag names, deliberately in the front end, because `dest=` spellings are an argparse fact and a library caller should not have to know that `--json` arrives as `args.json`. Its `run()` is a fixed sequence: `connect()` → `discover_documents()` → `filter_pending_documents()` → `process_notebook_item()` per doc. `process_notebook_item()` is itself a fixed sequence of stages — `_describe_job` → `_acquire_pages` → `_collect_tags` → `_preprocess_images` → `_ocr_pages` → `_write_transcripts` → `_judge_pages` → `_publish` — passing a mutable `DocumentJob` between them; a stage with nothing left to do raises `_StopProcessing(success, reason)` rather than returning a sentinel. **`_judge_pages` sits after the transcript, not before it**: its whole job is to stop a document from publishing, and a user debugging a run that published nothing needs the artifact that says what the model actually returned. `DocumentJob` is the pipeline's scratchpad and never leaves it: `_publish` calls `_build_document(job)` and `_publish_context(dest, doc_id)` to hand a destination the immutable pair, so a destination cannot reach back into half-finished pipeline state. `_ocr_pages` fans out over `settings.ocr_concurrency` threads (`core.stages.Transcriber.transcribe`) — a page is one network round trip, so this is where the wall-clock time goes; results come back in page order regardless of completion order. `--preview --transcribe` short-circuits `_publish`, so nothing is sent and no processed-log entry is written, leaving the notebook pending. Rendering is not in the pipeline at all — see seam 6. Test at the seam that matches: command-level in `test_cli.py`, order-level in `test_pipeline.py`, and a stage's own behaviour in `test_stages_*.py`.

**What a stage *does* lives in `core/stages/`; `pipeline.py` owns only the order.** Four are extracted so far — `preprocess.prepare_pages`, `transcribe.Transcriber`, `transcript.write_transcript`, `verdict.judge_pages` — and none of them takes a `DocumentJob`: a stage is handed the paths, the pages or the settings it works on, which is the difference between a module and a method that happened to move. `Transcriber` is a class rather than a function because the hit/miss tally is per run and the thread pool needs a lock around it; `pipeline._ocr_pages` reads `self.transcriber.hits` instead of keeping its own counters. Rule 4 in `tests/test_layering.py` applies to everything under `core/` (it globs recursively, so `core/stages/` needed no new rule), which is what pushed `log()` down into `living_ink.logs`: a stage that has to import the pipeline to say one line to the user has not been extracted. **The render and publish clusters cannot follow.** Rendering needs `living_ink.sources` and publishing needs `living_ink.destinations`, both of which rule 4 forbids `core/` from importing, and `_StopProcessing` / `DocumentJob` live in `pipeline.py` — so those two stay methods, on purpose, not by omission. `core/stages/transcript.py` keeps its `living_ink.extract` import function-level for the same §9.6 reason `sources/` does.

**The rest of `core/` is what both the run and the preview have to agree on.** `selection.select()` is the one classifier and the one candidate set — a preview that predicted something other than what the run does is worse than no preview, so `sync --preview` and `sync` call it with the same `SelectionCriteria`. It reads `recipe.py`, which digests everything *other* than the document that shapes the output (prompts, model, renderer versions, destination config); `version` answers "did the document change" and the recipe answers "would we produce different output from the same document", and `publications` records both. `listing.py` holds the handful of reads — title, folder, version, type — that answer "what is this" before anything is downloaded, and lives here rather than in `pipeline.py` precisely so the selector does not have to import the pipeline to read a title (`pipeline.py` re-exports them, so existing call sites are unchanged). `temp.py` is the per-document workspace. Every run accumulates a `report.RunReport` — one `DocumentOutcome` per document (published / skipped / failed, pages, transcribed vs. cached, destinations) plus run-level `warnings` — printed once at the end by `_print_summary()`, as a table or as JSON under `sync --json`. Anything a user should see *after* the log lines scroll goes in `report.warn()`, not `log()`. The report carries no dollar estimate on purpose: there is no authoritative price table per provider and model, so it reports API calls and lets the user apply their own rate.

**5. Every setting is declared once, in `config/schema.py`.** One `Setting(...)` entry per setting: the field name on `Settings`, its `config.yml` key, kind, default, help, env var, CLI flag, choices, `store` (config / credentials / env-only) and `legacy_keys`. `SECTIONS` does the same for sections. Nothing else enumerates settings — `validate.py` checks a config against `SETTINGS`, `settings.resolve()`/`explain()` iterate it, and it is what a flag generator or a config menu reads. `settings.py` holds no `FIELD_ENV_VARS` and no per-field config readers; adding a setting is **one schema entry plus one dataclass field**, and `settings._assert_parity()` raises at import (plus `TestSchemaParity`) if those two sides ever disagree. Renaming a key means adding the old spelling to `legacy_keys` on the setting that survived, not editing three call sites: `validate_config()` warns, `apply_status()` copies it forward in memory, and `Settings._pick` reads it as a lower-precedence layer.

**6. A document format is a registered source, not a branch.** `sources/` is a package: `base.py` (the `SourceType` record, the `Renderer` Protocol, `PageRef`, `PageDescription`, `RenderContext`, `SourceBundle`, `SOURCE_REGISTRY`, `register_source`) plus one module per format — `notebook.py`, `pdf.py`, `epub.py`. `SyncPipeline` holds no `_RENDERERS` table and no `_render_pdf`/`_render_epub`/`_render_notebook`; `_render_document()` resolves `source_for_name(job.doc_type)` and `_render_source()` calls the contract in a fixed order: `prepare` → `pages` → `text_layer` → `render` per page. Adding a format is a module in `sources/`, a `Renderer` implementation, one `register_source(SourceType(...))` call, and one import in `__init__.py` — nothing in `pipeline.py` changes.

The contract is shaped by three things `page_count()`/`render_page(i)` cannot express. **Page numbers are sparse**: a 400-page PDF annotated on three pages yields 12, 200 and 377, so `PageRef` carries `ordinal` and `number` as two separate facts and `job.source_hashes` is appended per *saved image*, never indexed by page number. **PDFs and EPUBs carry an embedded text layer** that bypasses OCR, so `text_layer()` exists and **a document with zero pages and a text layer is a complete result, not an empty one** — an unannotated PDF renders nothing (the "cover preview" it used to render was somebody else's title page, costing one OCR call per document). **`empty_is_skip` is a declaration, not a guess**: an empty notebook is a skip, a PDF that yielded neither pages nor text is a failure, and `_nothing_to_render()` reads the flag rather than branching on a name. `describe_pages()` is **batched** — labelling an annotated PDF means reading the document, and doing that per page is the bug row 6 fixed; it returns `PageDescription(label, breadcrumbs)` *parts*, not a formatted string, because the destination decides presentation.

Exactly one source sets `is_fallback` (`notebook`), enforced by `register_source`; `fallback_source()` raises rather than defaulting, so a failed import says so instead of quietly rendering everything as ink. `source_suffixes()` is the single list of embedded-source extensions — `ssh.py` and `extract.extract_raw_document_from_zip` read it instead of each carrying `("pdf", "epub")`. **Every `living_ink.extract` import inside `sources/` is function-level, and `tests/test_layering.py` enforces it**: hoisting them creates a cycle (`extract_raw_document_from_zip` reads the registry) *and* silently breaks the ~15 tests that monkeypatch `living_ink.extract.render_page_from_document_zip` — those tests keep passing, against the real renderer.

## Non-obvious behaviors

- **`tests/test_layering.py` is the import graph, enforced.** It parses module-level `living_ink.*` imports with `ast` (function-level and `TYPE_CHECKING` imports are deliberately exempt — that is how a module reaches across a layer for one value without taking the dependency) and asserts: `config/` imports nothing from the package except the two standard-library-only leaves `redact` and `safeio`, which cannot import `config` back; `destinations/` imports nothing from `cli`, `ui`, `scheduler`, `pipeline` or `setup_wizard`, and nothing from `core/` except `core.document`; `sources/` imports nothing from that same command layer nor from `destinations`, **and nothing from `extract` or `api` at module level** — every renderer reaches them from inside a method, which is both what avoids the cycle and what keeps the `render_page_from_document_zip` monkeypatches applying. `core/` imports nothing from `cli`, `ui`, `scheduler`, `pipeline`, `setup_wizard`, `destinations` or `sources` (`TestCoreIsBelowThePlugins`, which globs `core/**` — a new subpackage under it is covered the day it lands). That one carve-out is safe **only because `core/document.py` imports nothing from Living Ink at all** — `TestTheDomainModelIsALeaf` is what keeps it that way, and `TestTheWorkspaceIsALeaf` says the same of `core/temp.py`, which `pipeline` imports. `core/document.py` holds the types that travel between the pipeline and a destination (`Page`, `Document`, `PublishContext`, `PublishResult`); a destination must be able to name what it is given and what it returns without reaching back into the pipeline. The rule list grows with each package that lands — add the rule when you add the package, not later.
- **`tests/fakes.py` exists to run contracts nothing shipped runs.** `FakeApiDestination` is the only thing that closes the `PublishResult.external_id` → `publications.external_id` → `existing_id` loop end to end: Obsidian, the only shipped destination, identifies notes by frontmatter and reports no id at all. It is a real `Destination` subclass, not a `MagicMock`, so adding a member to the ABC breaks it; it is deliberately **not** `@register_destination`-decorated, because registering mutates a process-wide dict at import and would change what every other test sees. It has already caught one regression the other 2,000 tests missed (a state lookup keyed by `display_name` instead of `state_key`).
- **`tests/builders.py` is where a test says what it means and nothing else.** `make_document`, `make_page`, `make_context` and `make_both` fill in every field a test does not care about, so adding a field to `Document` or `PublishContext` is one edit here rather than a hundred across the suite — which is exactly what the twelve-argument `publish` cost. `make_both("Notes", "body", folder=("Work",))` returns the `(doc, ctx)` pair; it raises `TypeError` on a keyword that names no field of either, because a silently ignored keyword is a test asserting nothing.
- **Importing `pipeline.py` is side-effect free — keep it that way.** Config is read by `get_default_config()`, destinations are built by `get_default_destinations()`, and directories are created by `ensure_runtime_dirs()`; all three cache and are called on demand, not at module load. `TestImportPurity` in `tests/test_pipeline.py` asserts a bare import creates no directories and prints nothing. The path constants (`DATA_DIR`, `WHITE_DIR`, …) are still module-level, so tests patch those; anything that reads config or touches disk goes behind an accessor.
- **Settings are resolved once, not passed through the environment.** `settings.Settings.resolve(config)` merges the schema's layers into one frozen typed object; precedence is **flag > env var > credentials store > config file (current key, then `legacy_keys`) > default**, implemented once in `Settings._layers`/`._pick` — `resolve()` throws the provenance away, `explain()` keeps it, and neither re-implements the other. `SyncPipeline.__init__` passes this run's flags as the `flags=` layer of one `Settings.resolve()` call and stores the result as `self.settings` — it used to hold a frozen `SyncOptions` and merge it afterwards with `dataclasses.replace`, which was a second precedence ladder that had already disagreed with `_pick` about what `--limit 0` means — `pipeline.use_ssh`, `.limit`, `.folder` and friends are read-only views onto it. Two resolutions depend on an earlier one and are the only ones that may: `use_ssh`'s default follows the resolved `preferred_connection`, and the AI key's credential name follows the resolved `ai_provider` (which is why `ai_provider` is declared first). A blank string from the file is a *value* (`obsidian.attachments_folder: ""` means "beside the note"); a blank env var is an omission, which is what a shell means by it. Do **not** reintroduce the old `os.environ` write-back. The only env var `load_yaml_config()` still exports is the one a third-party SDK reads for itself (`OPENAI_API_KEY`). Callers with no config in hand (`api.get_rmapi()`) fall back to `Settings.from_env()`.
- **The repo is stateless.** Config resolves to `~/.config/living-ink/config.yml` (8-step lookup in `config.get_config_path()`, incl. `LIVING_INK_CONFIG` / `LIVING_INK_CONFIG_DIR`); runtime artifacts to `~/.local/share/living-ink/` (`LIVING_INK_DATA_DIR`). Never write tokens, credentials, or notebooks into the checkout.
- **Secrets are never in `config.yml`.** `living_ink.config` is a package: `paths.py` resolves locations, `validate.py` holds the schema, `credentials.py` stores the secrets — one file per credential in `<config dir>/credentials/`, written atomically at `0600` via `safeio.write_secret_atomic`, and registered with `redact` on every read and write. The directory is derived from the *resolved config path*, so `LIVING_INK_CONFIG` pointing at a second profile takes that profile's credentials with it. The name carries the provider (`ai.api_key.<provider>`, composed only by `credentials.ai_key_name()`), so switching AI providers and back does not destroy a key. `_VALID_NAME` is the path-traversal guard — a name is restricted, not escaped, because it is also a filename. Migration from the old locations (a key in `config.yml`, a token in `~/.rmapi`) **copies**: `migrate_secret()` never deletes the original, so downgrading does not mean re-pairing, and a stored credential always beats one found in an old location. Anything that renders a key goes through `credentials.mask()` (`AIza••••••••3f2a`), including `SettingOrigin.display()`. `config/__init__.py` re-exports the lot, so `from living_ink.config import X` is unchanged.
- **A setting is retired by `status`, never by deleting it from the schema.** An unrecognised section is a hard ERROR, so dropping a schema entry on the day its code dies stops every config that names it from loading. `Setting` and `Section` therefore carry `status` (`ACTIVE` by default, so the exceptions are the only thing that looks exceptional), and a *renamed* key is not retired at all — it becomes a `legacy_keys` entry on the setting that replaced it. `validate_config()` turns a status into a **WARNING** (deprecated names its replacement; removed says it is ignored) and `apply_status()` acts on it — dropping removed sections and *copying* a deprecated key onto its replacement, only when the replacement is unset. Today: `google_vision:` and `apple_notes:` are `REMOVED`; `openai:`, `destination:` and the top-level `use_ssh` are `DEPRECATED`. **No config file is ever rewritten** — mapping happens in memory at load time, so comments and ordering survive; `load_yaml_config()` returns `apply_status(...)` as its last act, which is why everything downstream only ever sees current spellings.
- **A failed page does not fail the document, and the order the verdict asks its two questions in is the contract.** `core/stages/verdict.judge_pages(pages, *, skip_empty, has_text)` returns `Blocked(success, reason)` or None, and `_judge_pages` turns that into `_StopProcessing`. Both of its verdicts mean *nothing came back*, and both present as empty text on every page — so **failure is tested first, and `skip_empty` additionally guards on `Page.error`**. Get that backwards and a notebook whose every page hit a 429 is reported "skipped: every page is blank", a success, never retried. Three carve-outs, each because something *did* come back: a page carrying text **and** an error is not empty (a truncated response carries both); `has_text` is a PDF or EPUB's own text layer, which makes the annotations missing rather than the document; and a partial document publishes with gap markers. The partial publish writes a `publications` row with `pages_failed`, which `core/selection._owes_a_publish` reads as still pending — that clause is the only thing stopping the gaps from being permanent, since the version and the recipe both still match. Retrying a 200-page notebook for three failed pages costs three API calls, because the other 197 come from the transcript cache.
- **Transcriptions are cached, and the cache is not a temp artifact.** `cache.TranscriptCache` stores each page's transcription under `DATA_DIR/transcripts/`, keyed by `sha256(page bytes + clean.transcription_fingerprint())` — the fingerprint covers the provider, the model, and both prompt files, so editing `ocr_prompt.txt` correctly misses. It lives outside the purged temp dirs on purpose: surviving the purge is what makes a repeat sync of an unchanged notebook free. An empty transcription is never stored (a blank page is usually a rate limit). `living-ink cache` shows, prunes, and clears it; `cache.transcripts: false` turns it off. This is also what makes a run **resumable**: each page is banked the moment it comes back, so Ctrl+C costs the page in flight and nothing else. `_run_recorded` records an interrupted run as `outcome="interrupted"` with the counts it reached (`_counts` advances per notebook, not once at the end), and `cli.main` turns the interrupt into exit code 130 rather than a traceback.
- **Rendered pages are cached the same way — every source, including the PDF composite path, which used to re-render on every run.** `cache.RenderCache` stores each page's PNG under `DATA_DIR/renders/`, keyed by `PageRef.source_key` plus `extract.renderer_fingerprint()`, the source's name, **that renderer's own `version`**, `settings.render_background` and the device's panel size, so an unchanged page skips rendering entirely. Both caches derive from one `cache.FileCache` base — a third cache is a subclass with a `suffix`, a `noun`, and a `get`/`put` pair. `renderer_fingerprint()` is now only the installed `rmc`/`rmscene` versions: the hand-bumped `extract.RENDER_FORMAT_VERSION` is gone, because one global number for three renderers meant a change to the PDF compositor threw away every cached notebook page. **Bump `Renderer.version` whenever that renderer's output changes.** `cache.renders: false` turns it off.
- **Temp artifacts are auto-purged.** `cleanup_temp_artifacts()` runs at pipeline start, after each notebook, and via `atexit`. When debugging rendering or OCR, always pass `--keep-temp` or the PNGs vanish before you can look at them; it also keeps the downloaded document zip, which is the `.rm` source a render bug actually needs. Nothing implies it: `--preview --transcribe` used to turn it on behind the user’s back, which is one flag quietly becoming two concepts, so the transcripts a rehearsal leaves behind are asked for explicitly or purged like anything else.
- **`extract.py` monkey-patches `rmc`** (`_patch_rmc()`) to control SVG background and bounds. Upgrading `rmc`/`rmscene` is the likely cause of blank or clipped page renders.
