# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

All tooling runs through `uv` — never raw `pip`.

```bash
uv sync --all-extras          # install deps (incl. dev)
uv run living-ink --help      # CLI: sync | watch | setup | status
uv run living-ink sync --notebook "Foo" --keep-temp   # single notebook, preserve artifacts
uv run living-ink sync --dry-run                      # transcribe but publish nothing
uv run living-ink sync --json                         # run summary as JSON
uv run living-ink status                              # health check + effective settings
uv run living-ink watch --interval 600                # sync every 10 minutes until stopped
uv run living-ink status --json                       # machine-readable health check

uv run ruff check .           # lint
uv run ruff format --check .  # format check (run `ruff format .` to fix)
uv run pytest -v              # full suite
uv run pytest tests/test_pipeline.py::test_name -v    # single test
./tests/test_docker.sh        # Docker build + smoke tests (slow)
```

Before committing: `uv run ruff check . && uv run ruff format --check . && uv run pytest -v`.

## Architecture

Pipeline: reMarkable tablet → download → render `.rm` → PNG → OCR/cleanup via LLM → publish to destinations.

Five seams matter more than the file list:

**1. Transport is a Protocol, and it is self-healing.** `transport.RemarkableTransport` is the whole contract (`check_connection`, `get_meta_items`, `get_doc`, `download`, `get_file_type`, `download_raw_file`, `get_tags`). `api.get_rmapi()` returns a Cloud client (`sync.py`, sync protocol v3/v4), an SSH client (`ssh.py`, USB at `10.11.99.1`), or a `FallbackClient` wrapping both. Every method goes through `FallbackClient._with_fallback`, so a new Protocol method needs one proxy line, not bespoke retry logic. A transport that genuinely cannot serve a call raises `transport.UnsupportedOperation` — never omit the method, because callers do not use `hasattr`. `tests/test_transport.py` fails if any shipped client drops a method. `get_rmapi()` takes the resolved `Settings` and no longer reads the environment itself; preference resolves from `--ssh`/`--cloud` flags → `REMARKABLE_PREFERRED_CONNECTION` env → `preferred_connection` config → `"ssh"`.

**2. Destinations are an ABC with per-destination state.** `destinations/` is a package: `base.py` (the ABC, the registry, `DestinationStatus`, `MergeUnit`, the two error classes), one module per destination, and `__init__.py` re-exporting the lot plus `build_destinations()`. **Registry order is publish order, and registry order is the import order in `__init__.py`, which is alphabetical** — "whose failure is reported first" is configuration, not an accident of an import statement. `AppleNotesDestination` (AppleScript via `osascript`, flattens folders) and `ObsidianDestination` (Markdown + YAML frontmatter + WikiLinks, mirrors the full reMarkable folder tree) implement it. Sync state is tracked **per destination** in `state.db` (`state.StateStore`, one `publications` row per `(doc_id, destination)` carrying the version, the `external_id`, and the `target` it landed on), so a notebook can be published to Obsidian but still pending for Apple Notes.

**Every publish returns a `core.document.PublishResult`** (`ok`, `target`, `external_id`, `detail`, `warnings`) — a destination never records where a note landed on *itself*. It used to set `last_external_id` and `last_target` as instance attributes for the caller to read back, which made every destination stateful across documents and left the two facts free to describe different notes. `_publish` writes `result.external_id` and `result.target` into the publications row and feeds them back next time as `existing_id` / `existing_target`, so a renamed or moved notebook **moves** its note (with its attachments) instead of growing a second one. `result.warnings` go to `report.warn()` via `_report_destination_warnings()` — on failure too, since that is the run whose warnings matter most.

**The state key is declared, never derived.** `Destination.state_key` is what a publication row is filed under; it was `type(dest).__name__`, so renaming a class silently made every document look new — every note rewritten, every `first_published` restarted. Both shipped keys are pinned to their historical class names; `register_destination` raises `TypeError` unless the class sets `state_key` in its own `__dict__` (an inherited one would make two destinations share rows). `display_name` is the cosmetic counterpart, free to change, defaulting to `config_key`. Read state with `state_key`, print with `display_name`, and never swap them.

**Construction never validates; `check()` reports and preflight refuses.** `ObsidianDestination.__init__` used to raise for a missing vault, `build_destinations` caught it into one warning, and the run then compared every document against zero destinations and exited 0 having published nothing. Now `check()` returns a `DestinationStatus(ok, detail, remedy)` — cheap, no round trip — and `SyncPipeline.preflight_destinations()` runs right after `connect()`, checking *every* enabled destination (not just the first to fail) and raising `ConfigurationMissing` if any fails or if none are enabled. `cli.collect_status` calls the same `check()` rather than keeping a second copy of the vault test.

**`merge_unit` says how much of an existing note a re-publish rewrites** (`MergeUnit.DOCUMENT` / `.PAGE`, `str`-mixin enum because the floor is Python 3.10). Both shipped destinations are `DOCUMENT` today; `--dry-run` reads it to promise the right thing before the run instead of after. Never branch on a class name to decide that.

The **document id is the identity**, not the title: `publish()` takes `doc_id`, Obsidian stamps it into the frontmatter as `living_ink_id` and steps around a same-titled note belonging to another document (`Notes (2).md`), and Apple Notes replaces by the note id it returned. A document that has publications but is absent from the tablet's full listing is an orphan: `_handle_orphans()` reports it and deletes nothing unless `sync --prune`, which calls `Destination.unpublish()` — refused by default, and refused by Obsidian for any note not carrying the matching `living_ink_id`. Adding a destination means: a module in `destinations/`, subclass `Destination`, declare `state_key`, implement `from_config(section, settings)` + `describe()` + `check()` + `publish()`, decorate with `@register_destination("<config section>")`, and add the import to `__init__.py` in alphabetical position. `destinations.build_destinations()` walks `DESTINATION_REGISTRY`, so nothing in `pipeline.py` needs editing. A `from_config` returning `None` (or raising) skips that destination with a warning instead of failing the run. Both shipped destinations read their **values from `settings`, not from the `section`** — the section decides whether the destination runs, the settings decide how — so a flag or an env var outranks the file without the pipeline reaching in to patch the built object. The legacy single `destination:` key is normalized into per-section config by `_apply_legacy_destination()`, and the settings it could carry name `destination.<key>` in their `legacy_keys` so they still resolve. Obsidian's frontmatter dates are three distinct facts, not one: `created` (kept from the existing note if present, else `first_published` from the state store, else the tablet's modification date, else today), `updated` (the tablet's own modification date — `DocumentJob.modified_date()`) and `synced` (today). `pipeline.to_datetime()` / `to_iso_date()` are the single place that reconciles the transports' disagreement about timestamp shape (datetime vs. ISO string vs. epoch seconds vs. the device's epoch milliseconds); parse timestamps there, not at the call site.

**3. AI is one universal OpenAI-compatible provider.** `providers.UniversalChatProvider` talks to Gemini, OpenAI, Ollama, Groq, OpenRouter, Mistral, Together, or a custom base URL — selected by `PROVIDER_PRESETS` (`providers.py:39`). `NoneProvider` disables cleanup (raw OCR passthrough). Any backend that speaks the OpenAI chat API is a **preset entry, not code**; one that does not is a `TextRepairProvider` subclass with a `from_config()` classmethod, decorated `@register_provider("<name>")`. `get_provider(settings)` takes the run's resolved `Settings` — never a config dict, because the API key is not in the config file — and checks `PROVIDER_REGISTRY` first, then the presets; a registered plugin's `from_config(settings)` gets the same object. `clean.configure(settings)` is the one call that builds the provider and records whether the AI pass runs at all (`clean.repair_enabled()`, `ENABLE_REPAIR`); it is called once per run from `load_yaml_config()`. Vision OCR and text repair are the *same* call path with different system prompts, loaded from `ocr_prompt.txt` and `cleanup_prompt.txt` (the only two prompt files; plain text shipped inside the package — edit these to change LLM behavior, not the Python). `clean.ocr_and_repair()` does OCR + cleanup in one multimodal request, and it is the *only* way a page is read: there is no second OCR backend, so a provider without vision support fails the preflight rather than degrading.

**4. CLI is Command Pattern; pipeline is a class.** `cli.py` registers `BaseCommand` subclasses (`SyncCommand`, `WatchCommand`, `SetupCommand`, `StatusCommand`) on `LivingInkCLI`, each owning its own `register_args()` + `run()`. `SyncCommand.execute_sync()` returns a bool so a caller can decide what a failure means; only `run()` exits. `WatchCommand` reuses both — it delegates `register_args` to `SyncCommand` and loops over `execute_sync`, surviving failed cycles and stopping on `ConfigurationMissing` or Ctrl+C, which is what the compose daemon service now runs. `SyncCommand` constructs a `SyncPipeline`, whose `run()` is a fixed sequence: `connect()` → `discover_documents()` → `filter_pending_documents()` → `process_notebook_item()` per doc. `process_notebook_item()` is itself a fixed sequence of stages — `_describe_job` → `_acquire_pages` → `_collect_tags` → `_preprocess_images` → `_ocr_pages` → `_write_transcripts` → `_publish` — passing a mutable `DocumentJob` between them; a stage with nothing left to do raises `_StopProcessing(success, reason)` rather than returning a sentinel. `_ocr_pages` fans out over `settings.ocr_concurrency` threads (`_transcribe_pages`) — a page is one network round trip, so this is where the wall-clock time goes; results come back in page order regardless of completion order. `--dry-run` short-circuits `_publish`, so nothing is sent and no processed-log entry is written, leaving the notebook pending. Rendering dispatches through the `SyncPipeline._RENDERERS` table (`pdf`, `epub`, anything else → handwritten notebook), so a new document type is one renderer method plus one table entry. Test at the seam that matches: command-level in `test_cli.py`, stage-level in `test_pipeline.py`. Every run accumulates a `report.RunReport` — one `DocumentOutcome` per document (published / skipped / failed, pages, transcribed vs. cached, destinations) plus run-level `warnings` — printed once at the end by `_print_summary()`, as a table or as JSON under `sync --json`. Anything a user should see *after* the log lines scroll goes in `report.warn()`, not `log()`. The report carries no dollar estimate on purpose: there is no authoritative price table per provider and model, so it reports API calls and lets the user apply their own rate.

**5. Every setting is declared once, in `config/schema.py`.** One `Setting(...)` entry per setting: the field name on `Settings`, its `config.yml` key, kind, default, help, env var, CLI flag, choices, `store` (config / credentials / env-only) and `legacy_keys`. `SECTIONS` does the same for sections. Nothing else enumerates settings — `validate.py` checks a config against `SETTINGS`, `settings.resolve()`/`explain()` iterate it, and it is what a flag generator or a config menu reads. `settings.py` holds no `FIELD_ENV_VARS` and no per-field config readers; adding a setting is **one schema entry plus one dataclass field**, and `settings._assert_parity()` raises at import (plus `TestSchemaParity`) if those two sides ever disagree. Renaming a key means adding the old spelling to `legacy_keys` on the setting that survived, not editing three call sites: `validate_config()` warns, `apply_status()` copies it forward in memory, and `Settings._pick` reads it as a lower-precedence layer.

## Non-obvious behaviors

- **`tests/test_layering.py` is the import graph, enforced.** It parses module-level `living_ink.*` imports with `ast` (function-level and `TYPE_CHECKING` imports are deliberately exempt — that is how a module reaches across a layer for one value without taking the dependency) and asserts: `config/` imports nothing from the package except the two standard-library-only leaves `redact` and `safeio`, which cannot import `config` back; `destinations/` imports nothing from `cli`, `ui`, `scheduler`, `pipeline` or `setup_wizard`, and nothing from `core/` except `core.document`. That one carve-out is safe **only because `core/document.py` imports nothing from Living Ink at all** — `TestTheDomainModelIsALeaf` is what keeps it that way. `core/document.py` holds the types that travel between the pipeline and a destination (today `PublishResult`); a destination must be able to name its own return type without reaching back into the pipeline. The rule list grows with each package that lands — add the rule when you add the package, not later.
- **`tests/fakes.py` exists to run contracts nothing shipped runs.** `FakeApiDestination` is the only thing that closes the `PublishResult.external_id` → `publications.external_id` → `existing_id` loop end to end: Obsidian identifies notes by frontmatter and reports no id, and Apple Notes — the only one that does — is on its way out. It is a real `Destination` subclass, not a `MagicMock`, so adding a member to the ABC breaks it; it is deliberately **not** `@register_destination`-decorated, because registering mutates a process-wide dict at import and would change what every other test sees. It has already caught one regression the other 2,000 tests missed (a state lookup keyed by `display_name` instead of `state_key`).
- **Importing `pipeline.py` is side-effect free — keep it that way.** Config is read by `get_default_config()`, destinations are built by `get_default_destinations()`, and directories are created by `ensure_runtime_dirs()`; all three cache and are called on demand, not at module load. `TestImportPurity` in `tests/test_pipeline.py` asserts a bare import creates no directories and prints nothing. The path constants (`DATA_DIR`, `WHITE_DIR`, …) are still module-level, so tests patch those; anything that reads config or touches disk goes behind an accessor.
- **Settings are resolved once, not passed through the environment.** `settings.Settings.resolve(config)` merges the schema's layers into one frozen typed object; precedence is **flag > env var > credentials store > config file (current key, then `legacy_keys`) > default**, implemented once in `Settings._layers`/`._pick` — `resolve()` throws the provenance away, `explain()` keeps it, and neither re-implements the other. `SyncPipeline.__init__` layers its `SyncOptions` on top with `dataclasses.replace` and stores the result as `self.settings` — `pipeline.use_ssh`, `.limit`, `.folder` and friends are read-only views onto it. Two resolutions depend on an earlier one and are the only ones that may: `use_ssh`'s default follows the resolved `preferred_connection`, and the AI key's credential name follows the resolved `ai_provider` (which is why `ai_provider` is declared first). A blank string from the file is a *value* (`obsidian.attachments_folder: ""` means "beside the note"); a blank env var is an omission, which is what a shell means by it. Do **not** reintroduce the old `os.environ` write-back. The only env var `load_yaml_config()` still exports is the one a third-party SDK reads for itself (`OPENAI_API_KEY`). Callers with no config in hand (`api.get_rmapi()`) fall back to `Settings.from_env()`.
- **The repo is stateless.** Config resolves to `~/.config/living-ink/config.yml` (8-step lookup in `config.get_config_path()`, incl. `LIVING_INK_CONFIG` / `LIVING_INK_CONFIG_DIR`); runtime artifacts to `~/.local/share/living-ink/` (`LIVING_INK_DATA_DIR`). Never write tokens, credentials, or notebooks into the checkout.
- **Secrets are never in `config.yml`.** `living_ink.config` is a package: `paths.py` resolves locations, `validate.py` holds the schema, `credentials.py` stores the secrets — one file per credential in `<config dir>/credentials/`, written atomically at `0600` via `safeio.write_secret_atomic`, and registered with `redact` on every read and write. The directory is derived from the *resolved config path*, so `LIVING_INK_CONFIG` pointing at a second profile takes that profile's credentials with it. The name carries the provider (`ai.api_key.<provider>`, composed only by `credentials.ai_key_name()`), so switching AI providers and back does not destroy a key. `_VALID_NAME` is the path-traversal guard — a name is restricted, not escaped, because it is also a filename. Migration from the old locations (a key in `config.yml`, a token in `~/.rmapi`) **copies**: `migrate_secret()` never deletes the original, so downgrading does not mean re-pairing, and a stored credential always beats one found in an old location. Anything that renders a key goes through `credentials.mask()` (`AIza••••••••3f2a`), including `SettingOrigin.display()`. `config/__init__.py` re-exports the lot, so `from living_ink.config import X` is unchanged.
- **A setting is retired by `status`, never by deleting it from the schema.** An unrecognised section is a hard ERROR, so dropping a schema entry on the day its code dies stops every config that names it from loading. `Setting` and `Section` therefore carry `status` (`ACTIVE` by default, so the exceptions are the only thing that looks exceptional), and a *renamed* key is not retired at all — it becomes a `legacy_keys` entry on the setting that replaced it. `validate_config()` turns a status into a **WARNING** (deprecated names its replacement; removed says it is ignored) and `apply_status()` acts on it — dropping removed sections and *copying* a deprecated key onto its replacement, only when the replacement is unset. Today: `google_vision:` is `REMOVED`; `openai:`, `destination:` and the top-level `use_ssh` are `DEPRECATED`. `apple_notes:` stays `ACTIVE` while the destination still ships. **No config file is ever rewritten** — mapping happens in memory at load time, so comments and ordering survive; `load_yaml_config()` returns `apply_status(...)` as its last act, which is why everything downstream only ever sees current spellings.
- **Transcriptions are cached, and the cache is not a temp artifact.** `cache.TranscriptCache` stores each page's transcription under `DATA_DIR/transcripts/`, keyed by `sha256(page bytes + clean.transcription_fingerprint())` — the fingerprint covers the provider, the model, and both prompt files, so editing `ocr_prompt.txt` correctly misses. It lives outside the purged temp dirs on purpose: surviving the purge is what makes a repeat sync of an unchanged notebook free. An empty transcription is never stored (a blank page is usually a rate limit). `living-ink cache` shows, prunes, and clears it; `cache.transcripts: false` turns it off. This is also what makes a run **resumable**: each page is banked the moment it comes back, so Ctrl+C costs the page in flight and nothing else. `_run_recorded` records an interrupted run as `outcome="interrupted"` with the counts it reached (`_counts` advances per notebook, not once at the end), and `cli.main` turns the interrupt into exit code 130 rather than a traceback.
- **Rendered pages are cached the same way.** `cache.RenderCache` stores each page's PNG under `DATA_DIR/renders/`, keyed by the page's `.rm` source plus `extract.renderer_fingerprint()`, `settings.render_background` and the device's panel size, so an unchanged page skips `.rm` → SVG → PNG entirely. Both caches derive from one `cache.FileCache` base — a third cache is a subclass with a `suffix`, a `noun`, and a `get`/`put` pair. `extract.RENDER_FORMAT_VERSION` is in the fingerprint: **bump it whenever `extract.py`'s rendering changes**, or the cache serves images the current code would not produce. `cache.renders: false` turns it off. The PDF composite path is not cached.
- **Temp artifacts are auto-purged.** `cleanup_temp_artifacts()` runs at pipeline start, after each notebook, and via `atexit`. When debugging rendering or OCR, always pass `--keep-temp` or the PNGs vanish before you can look at them. `--dry-run` implies `--keep-temp`, since the transcripts it points at would otherwise be purged on the way out.
- **`extract.py` monkey-patches `rmc`** (`_patch_rmc()`) to control SVG background and bounds. Upgrading `rmc`/`rmscene` is the likely cause of blank or clipped page renders.

## Conventions

- Google-style docstrings on all modules, classes, and functions.
- Branches: `feat/<description>`, `fix/<description>`.
- Preserve existing comments and docstrings in code you aren't changing.
